# elite-ppt-pro (vercel-labs/skills PR #813) — audit notes
Files: SKILL.md (624 l), references/slide-types.md (2393 l, 38 layouts as pptxgenjs JS functions), references/qa-checklist.md (102 l). No executable code, no tests, no renderer.
A. Problem: prompt-only skill to make "elite consulting" PPT via pptxgenjs, merging a multi-style layout library with a data-first McKinsey workflow.
B. Architecture: SKILL.md = 7-step workflow (research ≥15 data points/≥5 sources → plan → pick style → pick layout → write pptxgenjs code → optional HTML → manual QA). 8 theme palettes (A–G + McK navy). Helper JS functions (addEliteHeader, addDataSource, addPageBadge, addKPICard, addBulletPoints, addDataCard). slide-types.md: A1–A7, B1–B5, C1–C12, D1–D3, E1–E4, F1–F4, G1–G3 code snippets (SWOT, Ansoff, Pareto, Chasm, KANO, STP, RFM, Gantt, Journey, BMC, Porter triangle, 2x2, KPI dashboard, timelines...).
C. Flow: agent researches, writes a JS file by copy-adapting snippets, runs node, checks checklist by eye (no render step).
D. Strengths: research-first gate with quantified minimums + source tiering; "Source:" footer mandatory on data slides; conclusion-as-title rule with ✅/❌ examples; max 2 accent colours/page; data-type→layout recommendation table; standard 10-page consulting structure; wide framework coverage (SWOT/Ansoff/KANO/STP/RFM/BMC/Porter/Gantt/Journey); common-error table (hex without #, wrap:true, bounds x+w≤10).
E. Weaknesses: no code/engine — each deck re-written from snippets → inconsistency; "≥4 content zones per page" contradicts one-message slides and pushes density over clarity; headline at 10 pt in 0.55" band (too small for an action title); gradients, "smart icons", purple/orange themes, page badges, "Elite PPT Pro" watermark in every header → AI-slide look; charts drawn as rectangles (not native, not editable data); self-contradiction (says pptxgenjs lacks gradients, uses officegen syntax, then uses gradient in pptxgenjs); hard-coded coordinates everywhere; QA purely manual checklist, no render, no overflow measurement; mixed Chinese/English; storyline limited to a fixed 10-page template, no pyramid/SCR logic.
F. Reuse: research/evidence gate + source tier table; source-line convention; ≤2 accent colours; data-type→visual table; framework catalogue as *diagram types* (2x2, funnel, journey, Gantt, pyramid, value chain); common-error table idea → automated lint.
G. Discard: 7 colour themes, gradients, icons, page badges/watermark, ≥4 zones rule, pptxgenjs snippets, HTML dual output.
H. Reinterpret: "research first" → evidence register in the slide intent (each slide lists evidence + source); QA checklist → automated checks + semantic rubric; framework library → diagram primitives parameterised by data.
